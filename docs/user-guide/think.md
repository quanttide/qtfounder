# think load：从对话里看消耗落在哪

`qtfounder think load` 读 Hermes 的会话库，把说话人自己说的话过一遍，找出表达「耗」的句子，
判断这股消耗来自哪里、落在助手这一侧的哪个环节，每条都挂一句原话。

它不判「情绪好不好」，也不做情绪画像（那部分归 memory 五轴档案）。它回答一个问题：
**这股累是哪来的，我该改什么。**

## 命令

```bash
qtfounder think load                 # 读 ~/.hermes/state.db，判最多 200 条
qtfounder think load --dry-run           # 只统计候选量，不够模型
qtfounder think load --since 2026-09-01  # 只看这段时间之后的话
qtfounder think load --limit 40          # 本轮最多判 40 条（控成本）
qtfounder think load --out report.md     # 把完整报告写成 markdown（含原句，别放公开仓）
qtfounder think load --json              # 机器可读输出
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--db` | `~/.hermes/state.db` | 会话库路径，只读打开 |
| `--since` | — | 只取该日期（YYYY-MM-DD）之后的语料 |
| `--limit` | `200` | 本轮最多判多少条 |
| `--batch` | `20` | 每批送模型几条 |
| `--workers` | `4` | 并发几批 |
| `--top` | `10` | 来源清单列几条 |
| `--max-hits` | `0` | 命中数超过它就以退出码 1 结束；0 表示有命中就报 1 |
| `--out` | — | 完整报告路径（markdown） |
| `--dry-run` | — | 只统计候选量，不调模型 |
| `--json` | — | 输出 JSON |

## 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 没有命中（或命中数没超过 `--max-hits`） |
| 1 | 有命中（或超过 `--max-hits`） |
| 2 | 读不到会话库、没有可用密钥、调用失败 |

## 怎么判

写在 `src/cli/src/think/load/prompt.md`，改口径只改这份提示词，不事后改数据。

- 只判说话人**自己**的状态：技术提问、下命令、纠错、评价工具都不算
- 主语必须是他自己：「读者每处理一个点都要做判断」这类是在评论文档，不算
- 两类信号分开计：`fatigue`（真的累）与 `friction`（烦、返工、失控感）。混在一起会让
  摩擦淹没疲劳，两类数量常差三倍以上
- 每条来源必须带一句对应的原话，没有原话的判断不算命中（写死在解析里，不靠叮嘱模型）
- 责任全部记在助手一侧，只分环节：没说「双方都有」这个选项

## 五个环节

| 环节 | 含义 |
|---|---|
| A | 没照做、忘了、擅自改：说过的没记住、没按说的做、越权改动、放错位置 |
| B | 输出太复杂、看不懂：密度高、太长、名词没解释、看不出主线 |
| C | 没给判据、没法验证：他判不了对错、不知道怎么验收 |
| D | 没把选项收敛到能拍：他在两个方案之间纠结、不知道要写什么 |
| E | 没把外部条件的坑先探掉：数据接不上、通道不通、要等别人的结论 |

D 和 E 是刻意归到助手这边的：把一堆可能摆在他面前让他自己收敛、或者让他先撞上坑再发愁，
都是助手的失职。认不出的环节一律记 C，不回到用户身上。

## 凭据

`LLM_API_KEY` → `~/.pi/agent/auth.json` 的 `deepseek.key` → `~/.bashrc` 里的
`export DEEPSEEK_API_KEY=`。密钥只读不打印。模型与端点可换：
`LLM_MODEL`（默认 `deepseek-chat`）、`LLM_BASE_URL`。

模型调用 `temperature=0`、只收 JSON——同一批跑两次要给同一个结论，否则这条命令不可复跑。

## 隐私边界

- 语料只读不写：`state.db` 以只读模式打开，只取 `role='user'` 的消息
- 每次判断要调模型，所以消息正文会发到模型服务商；要纯本机就把 `LLM_BASE_URL` 指向本地端点
- `--out` 写出的报告含原句，别把它放进公开仓库

## 已知偏差

- 只有与助手的对话：当面聊的、会议录音都不在这里面
- 单模型单次判断，没有第二人复核；来源短语是概括，是「值得核对的假设」，不是因果
- 命中要求原话，语气很轻的累会被漏掉；未进池的条数会打印，但没做穿漏抽样
- 时间按消息发出时间算，不代表疲劳发生在那一刻

## 同组的另外两条

`think` 还带 `reflect`（按 CBT 那套记一条反思、到点回填行为实验）与 `model`（看当前生效的认知模型）。
两者的契约见 CLI 自己的文档：[think 用户指南](../../src/cli/docs/user-guide/think.md)。
