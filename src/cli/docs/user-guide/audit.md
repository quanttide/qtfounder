# audit：文字体检

把 `language` 与 `docs` 两套审计合起来，按「一个词、一条规则」归堆，每期只报一处最值得改的。

## 为什么只看一处

体检报告是给人读的，不是给机器看的。一次列一百条，读者只会关掉它；一次说一处，改完再来。

挑法是一个词、一条规则：改一次能带走很多处，说明那是同一道判断在几十个地方重复。

## 排序

术语优先。格式小事命中再多也只是小事；读者要先把词翻译一遍才读得懂的，才是先该动的那一处。术语清干净了才轮到格式。

## 报告长什么样

```text
量潮创始人 · 文字体检

这次看了 222 篇文档。

这一期先改一处：「判定」

它出现 53 次，落在 30 篇里。

怎么改：把「判定」换成 判断、看出。

另有 149 类这次不列，改完这一处再看。
机器拿不准的有 784 处，这类归人判，不进这份报告。
```

## 什么不进报告

目录级的体裁要求不进。`required` 在 line 0 的那类命中说的是整篇该是什么体裁，给不出逐处的替代写法，归人判。

三类误报不进：提及、标题并入、引用工具输出。

嫌疑也不进：机器拿不准的单独报个数，不混进本期该改的那一处。

## 与其他命令的关系

`audit` 不新加检查，只是把 `language` 与 `docs` 的结果并排看。标准不在它这儿：要换标准，改那两条命令或它们的契约。

## 存量巡检

`audit --patrol` 换一个问题：当年漏过去多少，后来又有多少被人改掉。

做法是抽一批历史提交，各自导出成一棵树，用今天的契约重判，再和今天逐条比。每个仓默认抽 40 个提交，两端必取，中间等距；给八九十次提交的小仓就是全取。

```text
量潮创始人 · 存量巡检

重判了 24 个仓、573 次快照。

历史上有 1405 处命中进过库，今天还在 284 处。
消失的 1121 处：1058 处随文件消失，63 处在留存文件里被改掉。

术语命中消失 491 处，其中 36 处改在留存文件里。抽检 36 条：19 条由术语清理提交改掉，17 条随改写消失。

按条数算，今天的体检还有 425 处真问题；上面按「同一文件同一规则」算，同一个词在多行命中只计一次。
```

三档分开是因为归宿不同。「随文件消失」不算有人改过，文件重写一遍，旧命中自动清零。「在留存文件里被改掉」才是有人动手，其中一部分是专门为这个词发起的清理。「今天还在」是仍然背着的存量。

最后那段抽查会回溯每条清理的提交，按提交信息里有没有「术语」「用词」「说法」「语用」「命名」分类。这是启发式：专门清理的提交会写清楚，改写顺带带走的不写。抽到的条数上限 40，够看出比例。

巡检慢，而且依赖 `git` 与系统的 `tar`。它不进提交闸门，只在需要基线时手动跑。

## 退出码

0 没查出真问题，1 有，2 契约读不了。
