# `qtfounder write` 用户指南

表达审计判的是这段文字有没有把话讲清楚，不看词法，也不看表格形状。四层：空话、口号、指路、结构。

## 一、四层查什么

**空话**：删掉不影响意思，或需要说清具体指什么的词，例如「进一步」「持续」「赋能」「抓手」。按整篇密度判，不逐句报；单个词出现一次可能只是正常用法。

**口号**：先否定再肯定（`不是……而是`）、只给条件不给反例（`只有……才`）、用递进代替论证（`越……越`）、用 `说到底`、`本质上` 收束。命中逐行报，代码块里的示例不算。

**指路**：正文里让读者去看另一份文档，例如「详见」「参见」「见某文件.md」。读者拿不到那份文档时，这句话就断了；结论应当写进正文。

**结构**：有没有一级标题、一篇是否只有一个、标题层级是否跳级、长文有没有按节分开。一级标题缺失报错误，其余报嫌疑。

## 二、分工

| 命令 | 管什么 |
|---|---|
| `qtfounder language` | 词与句：禁用词、句长、逗号、名词化 |
| `qtfounder docs` | 块形状：表格、列表、加粗、分割线 |
| `qtfounder write` | 表达方式：空话、口号、指路、结构 |

三层都跑，但同一处只改一次。

## 三、用法

```bash
cargo run -- write docs                    # 审文档站
cargo run -- write docs --kind slogan      # 只看口号
cargo run -- write docs --json             # 给下游用
cargo run -- write path/to/file.md         # 单文件必审
```

退出码：0 无命中，1 有命中，2 契约或文件读不了。

## 四、改法

命中先读上下文，再决定改不改。常见改法：

- 空话：删掉，或说清具体指什么。
- 口号：拆成条件、理由与反例；写不出反例，说明还没想清。
- 指路：把结论写进正文，路径只留一句去处。
- 结构：补一级标题，按节分开，每节只讲一个意思；标题层级一次只降一级。

契约在 `src/write/default-contract.toml`，词表与阈值改那里，不改判断层。
