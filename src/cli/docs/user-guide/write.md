# `qtfounder write` 用户指南

表达审计：先看体裁、读者、主题，再看句子形态。判的是这段文字有没有按它该有的样子讲清楚。

## 一、先定三个画像

同一段话，写进设计文档、路线图或 README，要求不同；给 Agent 看和给普通读者看，交代的密度也不同。`write` 先读三个画像：

| 画像 | 决定什么 | 可取值 |
|---|---|---|
| 体裁 | 骨架与禁区 | design、roadmap、readme、insight、review |
| 读者 | 内部标识能多密、要不要对读者说话 | human、agent、maintainer |
| 主题 | 哪些词必须先定义 | game、cli、writing |

声明方式：front matter 写 `genre:`、`audience:`、`topic:`；或命令行 `--genre`、`--audience`、`--topic`。都没给时，体裁按文件名推断，读者与主题用 default。

```yaml
---
genre: roadmap
audience: maintainer
---
```

`qtfounder write --profiles` 列出契约里现有的画像。

## 二、三轴各查什么

**体裁**：这类文本不能写成什么，内容该覆盖什么。设计文档要问题、定义、验证、原则、结论；路线图要顺序、达成标志、后置代价；README 要用途、用法；洞察要有能被推翻的判断，章节随论证走，不查标题顺序；评审要结论。体裁还带禁区，例如路线图不写「假说」。固定模板归 `docs/` 下的手册与规格；陈述型不定章节。

**读者**：一段里不同内部标识的数量上限，以及硬性读者有没有对读者说话。普通读者的上限最低，Agent 可以密一些。

**主题**：主题词用到了，就要有一节「定义」或「术语」；没有声明主题就不查。

## 三、四层句子形态

所有文档都跑，不区分画像。四层分别是空话、口号、指路、结构。

空话是删掉不影响意思、或需要说清具体指什么的词，按整篇密度判。口号是先否定再肯定、只给条件不给反例、用递进代替论证，逐行报，代码块不算。指路是正文里让读者去看另一份文档——结论应当写进正文。结构那一层报一级标题、标题跳级与长文分节。

## 四、分工

`qtfounder language` 管词与句：禁用词、句长、逗号、名词化。`qtfounder docs` 管块形状：表格、列表、加粗、分割线。`qtfounder write` 管画像与表达：体裁、读者、主题，以及空话、口号、指路、结构四层。

三层都跑，但同一处只改一次。

## 五、用法

```bash
cargo run -- write docs
cargo run -- write docs --genre design --audience maintainer
cargo run -- write docs --profiles
cargo run -- write docs --kind genre
cargo run -- write docs --json
cargo run -- write path/to/file.md
```

退出码：0 无命中，1 有命中，2 契约或文件读不了。

## 六、改法

命中先读上下文，再决定改不改。常见改法：

- 体裁缺节：补该有的节，或换一个更合适的体裁。
- 体裁越界：把不属于这类文本的内容删掉，或拆到另一篇。
- 读者负担：拆成表格，或换成读者能懂的说法；硬性读者补一句对读者说话。
- 主题缺定义：补一节「定义」或「术语」，第一次出现前先交代。
- 空话：删掉，或说清具体指什么。
- 口号：拆成条件、理由与反例；写不出反例，说明还没想清。
- 指路：把结论写进正文，路径只留一句去处。
- 结构：补一级标题，按节分开；标题层级一次只降一级。

契约在 `src/write/default-contract.toml`，画像与阈值改那里，不改判断层。
