# `qtfounder language` 用户指南

语言检查：判的不是语法和错别字，而是**这段文字是不是在跟读者说话**。

## 一、先用它查自己的文档

自举同样适用于文档：

```bash
cargo run -- language docs
```

本仓的 `docs/` 跑完，除接口参考里那几段枚举标识符的（见「已知误报」），没有别的命中。零命中不代表没问题，只代表没有自造术语、没有体系词缺失、没有数字无据、没有放错层的文件、没有长句与收尾句式。真要看「这段是不是在记操作」，得开语义层：

```bash
cargo run -- language docs --sense
```

拿它查主仓的 `docs/`（三十九个文件），摘要长这样：

```
合计 190 处（banned 126，numbers 2，syntax 53，voice 9）；审了 39 个文件，其中 31 个有命中
```

## 二、六层查什么

**放错层**：文件放错目录，比如「陈述型数据放进了 docs」。

**自造术语**：词表里的词出现一处报一处，每条都带替代写法。出库条件是「你自己也开始用它」。

**体系词**：规范目录里必须出现你的说法（比如 gallery 要有「错法」「判例」），一次都没有说明写歪了。

**数字**：只抓论据数字——百分比与总数计数（`N 处／次／条／份／行`），要求同句有分母（`占`、`共 N`、`其中`、`N/M`、日期）或出处（`实测`、文件路径、`.md`）。描述用的数字不管：阈值（`≥2 次`、`第 10 行`）、上限（`最多 10 条`）、估算与区间（`三四个人`、`人均 50–60 元`、`200 多元`）。

**句法**：一句超六十汉字、一句「的」超三个、一句逗号超五个、名词化超三个、单段超三百汉字。超一百字标 ERROR，只超六十标嫌疑——因为他自己认可的文字里 p99 才一百零一。

句式两条：一是把结论推回给读者的收尾，二是用件数代替内容（数字加「件」字，不分是在数条数还是给事情命名）。

**表格**：已迁出到 `docs` 子命令，与列表、密度一起判文档结构，见 [`docs` 用户指南](docs.md)。

**复核**：每批结果先过一层复核，把规则自己造成的误报挑出来——词被引号包着讨论（提及，不是使用）、加粗小标签被并进句子、抄的是工具输出（「合计 64 处」）。误报仍留在清单里并标「误报·」，同时报总数，不当通过。体裁错配与词的多义判不了，不在这层假装判过。

**语用**：一段里内部标识符超三个、又一句对读者的指代都没有，读者只能旁观。反引号里全是中文的不算内部代号（那是术语强调）。

## 三、用法

```bash
cargo run -- language docs                 # 只审规范文档
cargo run -- language . --scope all        # 连 exclude 也不放过（流水、第三方依赖一起审）
cargo run -- language docs --kind voice    # 只看一类
cargo run -- language docs --sense         # 顺带跑语义层
cargo run -- language docs --sense --limit 5
cargo run -- language docs --json
```

退出码：**0 无命中 / 1 有命中 / 2 契约或文件读不了**。

## 四、语义层怎么用

它是同一条命令的第二个档位，不是另一个工具：规则先跑（毫秒级、免费、可复跑），加 `--sense` 才把规则判不了的段送模型。

两条纪律：**只送规则挑出的段**（`voice` 与 `syntax` 命中），`temperature=0` 且只收 JSON——同一段跑两次要给同一个结论。

凭据从环境变量 `LLM_API_KEY`／`LLM_MODEL`／`LLM_BASE_URL` 读，或退到本机 `~/.pi/agent/auth.json` 的 `deepseek.key`。**刻意不依赖任何外部 SDK**：直连 HTTP，装到哪都能跑。

## 五、契约在哪

`src/cli/src/language/default-contract.toml`。查找顺序与 `code` 那份一样，也不内置兜底。

词表自查并进了审计末尾：禁用词若也出现在你自己的文风基准（`--pool`，缺省 `data/profile`）里，末尾会提示「可考虑出库」。

## 六、已知误报

**接口参考类的文档会被 `voice` 层整段命中。** 列举参数名、JSON 字段名、环境变量的段落，一段里十几个标识符、一句对读者的指代都没有——按验收标准就是「读者只能旁观」。但 API 文档的读者就是来查这些标识符的，这是本职不是失职。

这类命中眼下只能人判一次，不要为了让它变绿去改文档。要根治得给 `voice` 加一条豁免：**成串反引号标识符的列举段不算**。

**`判定层` 是五段流水的组件名，词表又禁了「判定」这个词。** 开发指南里「判定层」指代码那条流水里按契约算答案的一段，是组件名不是行文用词，所以留着；代价是它每次都被 `banned` 报出来。要消掉只有改名（比如「规则层」），名字归用户定。

**抄工具自己输出的「合计 N 处」** 会被 `numbers` 层报成论据数字没出处。复核层认这一形态，标「误报·引用输出」，不当真问题。

## 七、已知的验收标准缺陷

分母模式曾写成双层转义（TOML 字面量加正则），编译出来要求字面反斜杠，七条一条都不生效，2026-10-22 已修，测试 `denominator_patterns_actually_match` 钉住「有分母就放过」。
