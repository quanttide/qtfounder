# `qtfounder language` 用户指南

语言检查：判的不是语法和错别字，而是**这段文字是不是在跟读者说话**。

## 一、先用它查自己的文档

自举同样适用于文档：

```bash
cargo run -- language docs
```

本仓的 `docs/` 跑出来是零命中。零命中不代表没问题，只代表没有自造术语、没有体系词缺失、没有数字无据、没有落点违规、没有长句与表格滥用。真要看「这段是不是在记操作」，得开语义层：

```bash
cargo run -- language docs --sense
```

拿它查一个真语料仓（二十三万汉字规模），摘要长这样：

```
合计 1299 处（banned 316，numbers 25，required 28，syntax 626，table 31，voice 273）；涉及 123 个文件
```

## 二、七层查什么

**落点**：文件放错层，比如「陈述型数据放进了 docs」。

**自造术语**：词表里的词出现一处报一处，每条都带替代写法。出库条件是「你自己也开始用它」。

**体系词**：规范目录里必须出现你的说法（比如 gallery 要有「错法」「判例」），一次都没有说明写歪了。

**数字**：分母与来源都缺才报。阈值与序数不算统计量（`≥2 次`、`第 2 次` 都不需要分母）。

**句法**：一句超六十汉字、一句「的」超三个、一句逗号超五个、名词化超三个、单段超三百汉字。超一百字标 ERROR，只超六十标嫌疑——因为他自己认可的文字里 p99 才一百零一。

**表格**：列数、单元格长度、行数、有没有表头，以及「这段内容根本不需要表」。两列表本质是名词加解释，改列表更自然。

**语用**：一段里内部标识符超三个、又一句对读者的指代都没有，读者只能旁观。反引号里全是中文的不算内部代号（那是术语强调）。

## 三、用法

```bash
cargo run -- language docs                 # 只审规范文档
cargo run -- language . --scope all        # 连流水与报告一起
cargo run -- language docs --kind voice    # 只看一类
cargo run -- language docs --sense         # 顺带跑语义层
cargo run -- language docs --sense --limit 5
cargo run -- language docs --json
```

退出码：**0 无命中 / 1 有命中 / 2 契约或文件读不了**。

## 四、语义层怎么用

它是同一条命令的第二个档位，不是另一个工具：规则先跑（毫秒级、免费、可复跑），加 `--sense` 才把规则判不了的段送模型。

两条纪律：**只送规则挑出的段**（`voice` 与 `syntax` 命中），`temperature=0` 且只收 JSON——同一段跑两次要给同一个结论。

凭据从环境变量 `LLM_API_KEY`／`LLM_MODEL`／`LLM_BASE_URL` 读，或退到本机 `~/.pi/agent/auth.json` 的 `deepseek.key`。**刻意不依赖任何外部 SDK**：直连 HTTP，装到哪都能跑。

## 五、契约在哪

`src/cli/src/language/default-contract.toml`。查找顺序与 `code` 那份一样，也不内置兜底。

词表自查并进了审计末尾：禁用词若也出现在你自己的文风基准（`--pool`，缺省 `data/profile`）里，末尾会提示「可考虑出库」。

## 六、已知的判据缺陷

契约里的 `denominator_patterns` 写成了双层转义（TOML 字面量加正则），编译出来要求字面反斜杠，**两边实现都一致地不生效**。也就是说「22 处，占 22/30」照样会被报。这条已用测试钉住，谁修契约先看那条测试。
