# 测试

## 一、跑什么

```bash
cargo test                 # 全部
cargo test language::      # 只跑语言侧
cargo test -- --nocapture  # 看输出
```

当前规模：`code` 侧二十四例，`language` 侧四十一例。

## 二、三类测试，各有各的活

**真样本**：喂一段真会出问题的代码或文字，断言某层命中。

**反样本**：喂一段没问题但长得像的，断言零命中。反样本比真样本重要——只写真样本的检查会一路收紧到误报成灾。

**契约可变**：改契约里的数字，断言判定跟着变。这条是「契约真的在起作用」的唯一证据。

## 三、临时文件的坑

并行测试共用一个临时文件名会互相覆盖，表现为随机失败。

```rust
static COUNTER: AtomicUsize = AtomicUsize::new(0);
let path = dir.join(format!("sample-{}.md", COUNTER.fetch_add(1, Ordering::Relaxed)));
```

第十四轮踩过一次：加了三例新测试后 `banned_word_is_reported` 开始随机失败，原因是四个测试都写同一个 `sample.md`。

## 四、跨实现的对等测试

`language` 从 Python 版迁到 Rust 时，最好的验收不是读代码，而是**同一份语料两边跑，比对命中**。

判等口径是三元组「层 + 路径 + 行号」。第一轮：六层完全一致，`voice` 层多报三十三条——原因是子串去重被我写成了空实现。补上后两边都是一千二百九十九处、按类分布完全相同。

这类比对只做一次不够，改完判定层要重跑。它抓到的东西，单测抓不到。

## 五、测试文件不适用「顶层定义过多」

`tests.rs` 里一屏二十个 `#[test]` 是正常的。`code` 对测试文件豁免这一条，否则每加一条测试都要跟工具吵架。
