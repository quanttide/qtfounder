# 文档审计路线图

从验证核心假设到阈值标定，分三步。每一步都有明确的停止条件，不通过就不往下走。

状态：阶段一与阶段二已随 `cli/v0.0.3` 落地；阶段零的语料验证与阶段三的标定还没做，密度阈值保持关闭。

## 阶段零：先验证假设

在写代码之前先人肉验证。从阶段三的两组语料里各抽五篇——手写的从 `data/journal/default/` 取，AI 的从 `data/profile/` 取——数一下三段式列表项占列表项的比例，把数字记下来。

两组有明显分离（比如手写两成、AI 七成），规则成立，往下做。没有分离，说明核心直觉是错的，写代码也是白写。这一步成本半小时，收益是避免为错误假设实现一整套规则。

验证时顺带标定两件事：列表项字数的合理上限写在哪，以及哪些文档体裁本来就用条目写（规格、清单类文档不吃这一套）。

## 阶段一：拆出 docs 层（已完成）

把表格判定从 `language` 迁出，独立成 `docs` 子命令，再在同一入口上加列表层：

1. 新建 `src/docs/`，把 `src/language/table.rs`、契约里的 `[table]` 段与 `Kind::Table` 整层迁入，契约文件落为 `src/docs/default-contract.toml`；`language` 同步删掉这三处，不留两份口径。
2. 在 `main.rs` 注册 `docs` 子命令，参数沿用 `root`、`--rules`、`--kind`、`--top`、`--json`，并为阶段二的观测加一个 `--stats`；索引一致性检查作为它的 `docs check` 子命令。
3. 新增列表层 `src/docs/list.rs` 与 `[list]` 段，至少三个字段：单项字数上限、三段式占比上限、列表项数下限（少于这个数不算结构块）。零值表示关闭，与其他层一致。
4. 行级扫描即可，不需要引 Markdown AST：识别 `- ` 与 `1. ` 开头的块，逐项统计字数，匹配 `**加粗**：` 前缀的比例；报告的四个要素不变，行号指向块起始行，建议写明整段重写为散文还是拆项。
5. 测试补齐真样本与反样本。反样本是关键：一段每项都加粗但确实是清单的文档，必须不报。

停止条件：迁移后原有表格用例在新命令下结果一致；十篇语料跑下来，列表误报集中在清单体文档且可以通过体裁排除解决。做不到就先别加列表规则。

迁移同时改文档站：`user-guide/language.md` 里表格那一层删掉，`api-reference/language.md` 的 `--kind` 枚举去掉 `table`；新增 `user-guide/docs.md` 与 `api-reference/docs.md`，`myst.yml` 目录同步。

## 阶段二：密度兜底（代码已完成，阈值待标定）

缺陷规则没命中、但整体仍像 AI 时，密度指标负责提示，挂在 `docs` 命令下与表格、列表同一份报告。它判的是整篇文档，不是某一行。

### 怎么算

先把正文切成块。标题、代码块、引用块、frontmatter 不算；连续的 `- ` 或 `1. ` 行为一个列表块；连续的 `|` 行为一个表格块；其余非空行为段落块。「字数」统一定义为去掉空白后的字符数，中英一致，不用汉字数。

两个指标都由块序列算出：结构块占比是表格块与列表块的字符数之和除以正文总字符数；无散文率是没有过渡段落的连续结构块除以结构块总数。过渡段落指两张列表或表格之间至少 `min_paragraph_chars` 字、且不属于另一个结构块的段落。

### 契约与判定

契约加 `[density]` 段，四个字段：`max_block_ratio`（结构块占比上限）、`max_run_ratio`（无过渡段落的块占比上限）、`min_paragraph_chars`（多长才算过渡段）、`min_chars`（文档总字数低于它就不判，避免拿短文档下结论）。零值关闭，与其他层一致。

严重度定死在嫌疑，不出错误。同一个文件最多报一条，挂在最长的那串连续结构块的起始行；建议里写占比、上限与改写方向，不逐行罗列。

去重规则：该文件只要有表格或列表的缺陷命中，密度就不报——已经指出具体位置，再补一条整体判断只会淹没有用信息。

### 先观测再判定

阈值先全部留空，用 `docs --stats` 把每篇的块占比、无散文率与字数打成一行，不产生命中。跑完阶段三的语料再回填数值；在填之前，这个选项只是把数字摆出来，不下结论。

### 测试

真样本：连续三段列表、中间没有段落的文档；结构块过半的说明文。反样本：带过渡段落且占比低于阈值的规格文档；总字数低于 `min_chars` 的短文档；代码块里写满表格与列表的教程。后三种必须不报。

## 阶段三：阈值标定

标定不能拍数字，要拿两组已知来源的文档跑。每组十五篇，按路径排序后等距抽取，不看完内容再挑。

手写组取 `data/journal/default/` 2026-03 至 2026-10 每月一两篇，加 `data/journal/work/2026-10/` 三篇。这批是手机或口头录入、没经过 AI 改写的原始文本。

AI 组取 `data/profile/think/` 九篇、`data/profile/work/` 五篇、`data/roadmap/` 一篇。这批是 AI 从日志蒸馏出来的成文，来源单一，不会把人的修改混进来。

另备一组只跑不标定：`docs/specification/` 与 `docs/tutorial/` 的清单体页面。这类文档本来就用条目写，用它们确认误报能被体裁排除；排除手段是目录白名单，不是把阈值放宽。

标完看两组分布：三段式占比取手写组最大值与 AI 组中位数之间的偏手写一侧，密度阈值取两组 P50 与 P90 之间。两组的体裁差异会抬高 AI 侧的密度，所以宁可少报——漏报的代价是报告少一行，误报的代价是整份报告被忽略。

十五篇只够定方向，不够定死。第一版阈值先落盘并注明语料范围，跑满三个月真实日志后再回看。在那之前，工具的价值是观测，不是判定——凭空定的数字不算数。

## 风险

核心直觉错误的代价最大，所以把验证放在最前面；误报会让整份报告被忽略，所以只报 top N，规则可逐条关闭，体裁不适用的目录直接排除；规则膨胀的护栏是每加一条必须自带替代动作。

## 验收

拿真实文档跑一遍，报告贴回 AI，它能按位置改完，复跑达标。做不到这一条，规则就不算做完。
