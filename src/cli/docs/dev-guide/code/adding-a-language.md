# 加一门语言

目标：判定层一行不改，只加一份 `LangSpec`。做不到这一点，说明提取器还带着语言假设。

## 一、五步

1. 在 `Cargo.toml` 加对应 tree-sitter 语法包；
2. 在 `src/code/extract/specs.rs` 写一个返回 `LangSpec` 的函数，十七个字段填全；
3. 在 `src/code/extract/mod.rs` 按扩展名挂上分支；
4. 用一门已知良好的代码文件试跑，**逐条核对命中是否真实**；
5. 补测试：至少一条「这个语言的函数名与参数个数算对了」。

## 二、字段里最容易填错的三处

**`name_path`**：从函数节点走到名字的下钻路径。Go 的名字直接挂在函数节点上，填空数组；Dart 要先进入 `signature` 字段，填 `["signature"]`。填错的症状是函数名全是 `<anonymous>`。

**`param_item_nodes`**：只有这些节点才算「一个参数条目」。Go 曾把 `parameter_declaration` 里的类型标识符也数成参数，六个参数报成十二个。

**`false_nodes`**：常量假条件的节点名。填错的症状是死代码一条都报不出来，而你不会察觉——它静默地不报。

## 三、口径差异要写进文档，不许假装生效

tree-sitter 提取器目前覆盖不了三条验收标准：调用链长度、文档复述、名实不符。原因是这三条要判定「调用者的意图」，通用节点名给不出足够信息。

**处理办法是写进用户指南的「暂缺」一节**，而不是让它静默返回零命中。工具静默跳过一条检查，比它报错更危险。

## 四、验收

加完语言后跑三件：

```bash
cargo test                                    # 单元测试
cargo run -- code <该语言的仓> --top 3        # 抽查命中是否真实
cargo run -- code src                         # 自查不退化
```

第三条是关键：新语言不该让 Rust 自己的命中数变化。变了说明你在提取层动了共用代码。
