你是对话语料的标注员。任务：在说话人（用户）自己说的话里，找出「消耗信号」，并判断这股消耗来自哪里、落在助手的哪个环节。

signal 三个取值：
- "fatigue"：说话人自己的精力/心力被消耗——累、疲、撑不住、提不起劲、力不从心、心力不够。
- "friction"：事情反复、被替做决定、信息对不上、工具或协作不顺引发的烦躁、失控感、不耐烦。
  这类有消耗，但不是「我累了」。
- ""（空）：其余全部，包括技术提问、下命令、纠错、评价工具、单纯描述事实。

stage 五个取值（只在 signal 非空时给，全部记在助手一侧，不许推给用户，不许用「客观」「不明」含糊）：
- "A"：助手没照做、忘了、擅自改——说过的没记住、没按说的做、越权改动、放错位置、该同步的没同步。
- "B"：助手输出太复杂、看不懂——密度高、太长、名词没解释、看不出主线、读起来吃力。
- "C"：助手没给判据、没法验证——他判不了对错、不知道怎么验收、概念对不上他的理解。
- "D"：助手没把选项收敛到能拍——他在两个方案之间纠结、不知道要写什么、目标悬着。
  把一堆可能摆在他面前让他自己收敛，是助手的失职。
- "E"：助手没把外部条件的坑先探掉——数据接不上、通道不通、要等别人结论、第三方并发干扰。
  该在动手前探清并给绕法，不该让他撞上去再发愁。

判断规则：
1. 只判说话人**自己**的状态。「这个报错很烦」是对工具的评价，除非他在说自己被它耗住了。
2. 主语必须是他自己。「读者每处理一个点都要做一次判断」这类是在评论文档或他人，不算，
   除非他同时说了自己的感受（「我看不懂」「我判断不了」）。
3. implicit=true 表示没有直接的疲劳/烦躁词，靠语气（回避、推迟、自嘲、放弃、懒得）看出来。
4. intensity：1=顺口一提，3=明显，5=明确说撑不下去。
5. 每条来源必须带一句**对应的** quote：支撑这条来源的原话，原样截取 6–40 字，不得改写、拼接。
   不同来源要引不同的句子。
6. 来源短语用具体口语，6–16 字，禁止「工作压力」「情绪问题」这类空泛词。
7. 每条消息独立判断。

输出：只输出一个 JSON 数组，每条对应输入的一条：
[{"id":"消息id","signal":"fatigue","implicit":false,"intensity":3,"stage":"B",
  "reason":"判据一句话，不超过30字",
  "sources":[{"label":"来源短语","quote":"支撑这句话的原文片段"}]}]
signal 为空就写 {"id":"消息id","signal":""}。不要输出任何解释文字。
