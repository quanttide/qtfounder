# 待办的收与抽

把一句「这事儿还没做」变成一条待办，攒成池子后按优先级抽一件开工。命令是 `qtfounder execute ...`，接口见 CLI 文档的 `execute` 段。

两件事：收一件（`execute collect`）、抽一件（`execute draw`）。收在协作现场做，抽在要动手时做。

## 待办的形状

待办长得像一句能直接开工的话，不是一个话题。永远先把候选写出来让用户改，不空手问「你想做什么」。

开口就一行加一句问：

```text
先记着：给 qtcloud 补 design review 的 Flutter 解析
要不要收？
```

用户要做的动作只有一个：回「对」，或改这一行。改一个字也算。

记完只回一行：`已收 tdo_xxx（优先级 N）：那一句话` + `池里待抽 M 件`。不复述流程、不解释设计。

## 收的纪律

- 由轻到重三级：A 命中推迟信号直接入账并一行回执（事后可改可删）→ B 收尾主动盘点一次（每次任务只提一次）→ C 用户召唤先定位对象再开口。
- 待办的验收标准要宽：凡是「现在不做、但确实要做的」就算——用户口头答应的、做到一半岔出的分支、你自己发现的欠账，都收。收得太窄，池子会只剩大任务，而那些「顺手就能记」的正是这工具存在的理由。
- 分界看「现在做还是以后做」：现在就该做的 → 直接做，不入池；明确推迟的 → 收。别拿它当挡箭牌去挡「现在就该做的事」。
- 主动但节流。同一类推迟一次会话只提一次；用户说「不用记」则该会话不再提这一类；提示只有一句，不解释、不展开、不打断手头的活。
- 主动触发只认明确信号，不做情绪检测。没有信号就不出声；不猜、不劝、不复盘用户的心情。
- 产出场景不打断。用户在写分析、写文档、推方案时那是在产出，不是在排待办——不在这种时候插收集。只在「他说了先放着」且确实还想做时开口。
- 只收一件事。一次一条，不打包；两件要记就记两条，第二条等第一条确认完再提。
- 判断都在 agent 侧：把「qtcloud 那块」翻成一句能开工的话、判断两句话是不是同一件、决定优先级给几，都是 agent 的活，用户只点头或改字。
- 优先级只认明说。用户说「这个急」「先做这个」才给 `--priority`，没说就不给（缺省 1）。不替用户排优先级——排错了，抽签就永远先抽错的那件。
- 写库两条路：A 级命中明确信号不必先问，直接记，回执一行并附「不想要就说删」；用户点头回应提示；用户已在消息里把要做什么说清楚，直接记并回执一行。两头都不清时才问一句。过门槛的成本必须低到「你什么都不用做」。
- 记歪了手改记录库文件重来（`execute.json`）；删除同样无命令，手改文件。
- 数据放哪由 CLI 自己选，不用 export。开发构建落代码包内 `src/cli/data/`，发布构建落 `$XDG_DATA_HOME/qtfounder`（未设则 `~/.local/share/qtfounder`）；只有跑实验、造夹具时才用 `QTFOUNDER_DATA` 指到临时目录。

## 前置

```bash
command -v qtfounder || echo "先装 qtfounder"
```

## 收集工作流

### A · 命中推迟信号直接入账（一行回执）

命中任一信号就收一件，不必先问：

- 用户说「先放着 / 以后再 / 之后再说 / 待办 / TODO / 下次」；
- 一件事做到一半岔出分支，用户说「这个先跳过」；
- 你自己发现的欠账（漏了测试、文档没更新），且不在本次范围内。

动作：自己把它写成一句能开工的话，进 `execute collect`，然后一行回执——`已收 tdo_xxx：<那一句话>，不想要就说删`。不解释、不展开、不打断手头的活。

用户说「不用记 / 删掉」→ 删掉这条（手改记录库文件），本会话不再记这一类。

### B · 收尾主动盘点（每次任务只提一次）

任务交付时扫一遍本次会话：有没有说过「先放着」却没收的，有没有发现的欠账。有就收，并把池子报一句：`池里待抽 M 件，要抽一件开工吗？`

### C · 用户召唤

召唤不等于「已有对象」。按顺序：

1. 先定位对象：用户说「收待办」时，能从上下文认出是哪件，就直接按「待办的形状」写出那一行让用户改。
2. 认不出就问一句：「要收哪一件？」——只问这一句，不上两问。
3. 对象明确但一句话还不清，再问：这件做完的标志是什么？答得笼统（「就是那事儿」）追问一次「哪件事儿，一句话」。追问后仍笼统，就记用户实际说的那句，不替他编。

### 收一件

```bash
qtfounder execute collect "给 qtcloud 补 design review 的 Flutter 解析" --priority 2
```

批量走 stdin，`--json` 拿结构化结果：

```bash
qtfounder execute collect --stdin --json <<'JSON'
{"todos":[
  {"text":"给 qtcloud 补 design review 的 Flutter 解析","priority":2},
  {"text":"发 CLI v0.1.0"}
]}
JSON
```

同文本已在池子里的只收一次，`deduplicated` 报跳过了几件。把回执那一行给用户，不贴大段 JSON。

### 抽一件开工

要动手却不知道先做哪件时：

```bash
qtfounder execute draw --json
```

没有优先级信息就均匀随机；有就按优先级加权——`priority` 是抽签的权重，越大越容易抽中，缺省 1，0 的签永远抽不中（收的时候就拒了）。抽走的进 `drawn` 留痕，不自动放回。

抽中就把那件报给用户：`抽中 tdo_xxx（优先级 N）：<那一句话>`，然后开工。抽签的意义就是省掉挑选的犹豫，别抽完又问「要不要换一件」。

## 示例

```text
（A 级：用户说「这个先跳过」）
用户：工作室的验收弹窗先跳过，回头再做
agent：（自己收，不问）
       已收 tdo_K2M9：给验收弹窗补被判断为工作物的本体展示，不想要就说删。

用户：这条不用记
agent：（手改 execute.json 删掉，本会话不再记这一类）

（B 级：任务收尾时）
agent：（扫一遍会话，收两件）
       已收 tdo_R7XA：发 CLI v0.1.0。
       池里待抽 2 件，要抽一件开工吗？
用户：抽
agent：（跑 draw）
       抽中 tdo_R7XA（优先级 1）：发 CLI v0.1.0

（C 级：召唤但没有对象）
用户：/execute-collect
agent：要收哪一件？
```

## 排错

错误一律是 JSON、写在 stderr，退出码三档：

| 码 | 含义 | 常见原因 |
|----|------|---------|
| 0 | 成功（含去重） | — |
| 2 | 用法错 | 位置参数与 `--stdin` 同给；`--priority 0`；待办文本为空；stdin 没有 `todos` 字段 |
| 3 | 未找到 | 池子是空的就 `draw`（先跑 collect） |
