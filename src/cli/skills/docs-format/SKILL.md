# 文档格式规范

遵循《量潮科技文档格式章程》（完整条文见 `references/format.md`）。适用于所有正式 Markdown 文档；个人笔记、临时草稿不受约束。

## 核心原则：格式克制

- **删**：删除不必要的格式元素，优先用段落和标题组织内容；
- **简**：能用列表即不使用表格，能用文字即不使用列表；
- **少**：全文格式元素的数量控制在必要的最小范围内；
- **一**：同一概念全程使用相同名称，不得混用不同术语指代同一事物。

## AI 写作约束

AI 是格式执行工具而非格式决策者。提交前检查并清除 AI 常见的格式过度行为：滥用分隔线、内容一律列表/表格化、使用「非常」「简单的」「显而易见的」等冗余修饰词。

## 结构规范

- 标题最多三级（`#` / `##` / `###`），不得继续嵌套更深层级；
- 一级标题仅文档主标题使用一次，全文不得出现第二个；
- 标题简洁、明确概括内容，避免在标题中使用标点；
- 标题与正文之间、章节之间以空行分隔；
- 中文文档标题使用中文；英文文档标题使用句子大小写（仅首字母大写，专有名词除外）；
- 分隔线（`---`）：优先用空行加标题区分章节；仅用于重大划分节点，全文不得超过三处；可用于文档顶部元信息与正文之间，不可在章节间重复使用；不得作为视觉装饰。

## 排版要素

- **无序列表**：用 `-` 标记；用于并列要点、不分先后、一两句说完的内容；列表项以分号结尾或使用完整句，全文风格一致；列表项不超过两行（超过改段落）；嵌套不超过两级，缩进两个空格；
- **有序列表**：用 `1.` 标记（渲染器自动编号）；用于有明确顺序的步骤、操作流程、排名或优先级；每个步骤表达完整；
- **列表使用限制**：仅描述单一事物时、列表项超过两行时、内容存在逻辑承接关系需要段落表达时，不得用列表代替正文；
- **代码块**：必须标注语言类型以便语法高亮；行内代码用反引号包裹（如 `variable`、`file.md`）；
- **表格**：仅用于呈现多维度、需对比的数据；表头加粗，列对齐使用冒号（`:--` / `:--:` / `--:`）；单元格简洁；仅简单的名称-定义对应关系、两列且无对比需求、单元格需完整句子时不得使用表格；
- **链接**：外部链接用 `[链接文本](https://example.com)`；内部链接用相对路径 `[文档](./docs/guide.md)`；
- **加粗**：仅用于首次定义关键术语、强调重要操作或警告、引导注意力到关键信息；不得对普通名词加粗；不得连续多个加粗；不得在列表项内部使用加粗；
- **块引用**（`>`）：仅用于标注重要提示或引用内容，不得作为正文的替代格式；
- **引号**：用于直接引用他人话语、首次定义术语、强调词汇特殊含义、标注界面元素名称；中文文档用直角引号「」，英文文档用双引号 `"`；不得对普通名词加引号、在列表项或标题中频繁使用、用引号包裹整句（改用块引用）。

## 提交前检查清单

1. 格式克制：无多余分隔线、无处处列表/表格化、无冗余修饰词；
2. 标题层级不超过三级，一级标题全文唯一；
3. 无连续加粗、列表项内部无加粗；
4. 表格仅用于多维度对比场景；
5. 术语全文一致，不混用；
6. 中文文档引号使用「」，英文使用双引号。

提交前可跑 `qtfounder docs format <文件>` 看格式状态（标题、表格、列表、加粗、分割线、块引用、代码块各几处）与审计命中；数字与命中共用同一处识别，先看数再读结论。
