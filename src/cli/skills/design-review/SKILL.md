# 交互设计评判

适用于一切带界面的交付物（页面、工作台、原型、示例）。评审与实现都按此执行。完整条文与评分表见 `references/principles.md`。

## 先立问题，再做屏幕

1. 动手前写下「用户打开这个屏幕时心里的问题」，每个界面元素必须能追溯到它；
2. 第一屏回答用户的第一个问题（通常是「现在该我干什么」），而不是展示系统结构。

## 减分项（违反即减分）

3. **工作物可见**：用户对着被加工的对象干活。只有任务清单而没有工作物本身（文档、数据、草案）的是任务管理器，不是工作空间；
4. **状态即邀请**：什么在等我、什么就绪了，通过视觉优先级直接呈现，不靠逐个读标签；就绪要有调度语义（上游完成判断），不能只画依赖；
5. **主行动唯一**：全屏只有一个主按钮层级，其余退后、折叠；
6. **动作有回应**：每个操作都有可感知的反馈（toast、高亮、完成时刻）；没有回应的点击等于界面失信；
7. **不演戏**：模拟的能力诚实标注；假延迟、假动画冒充智能比不做更糟；
8. **验收有对象**：通过 / 驳回时必须展示被审查的工作物本体，不允许只看一行摘要；
9. **中文微排版**：正文 ≥ 14px，辅助文字 ≥ 12px；更小的中文文字一律视为缺陷。

## 交付纪律

10. **脑内渲染走查**：提交前以用户角色走查整屏——第一眼看哪、第一步做什么、动作之后世界如何回应。看 spec 与代码就要能预感手感，不等「跑起来再说」；
11. **敢于自评分**：交付时按评分标准给出分数与理由；不敢给分等于没有内部标准；
12. **分数在走查之后**：自评分必须以第 10 条走查为前提，走查发现的缺陷未清零不得交付——先给分后走查，分数就是拍脑袋。

## 机器帮得上的两条

十二条里能机械判的只有两条的数字面，跑 `qtfounder design review <目录或文件>`：

- 第 9 条的字号：数 CSS 里的 `font-size` 声明，低于 12px 报缺陷，12–14px 报嫌疑（分不出正文与辅助）；rem 按 16px 根字号换算，`em` 相对父级判不了，只计数不换算；
- 第 5 条的主按钮：数 class 含 `primary` 的按钮，一个文件里多于一个报嫌疑——多屏合订本可豁免，逐屏自查。

`qtfounder design principles` 打印十二条全文。数字先看，结论再读；其余各条机器判不了，归走查与自评分。
