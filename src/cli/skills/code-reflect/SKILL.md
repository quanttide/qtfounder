# 任务完成后的架构反思

## 反思的形状

反思问的不是「这轮有什么 bug」——bug 归这次任务的验收。问的是**这轮干完，架构里多了什么以前没有的毛病**。

四条清单在 `src/code/default-contract.toml` 的 `[[reflect]]`，每条三层：看什么、为什么算缺陷、长什么样。缺省只打前两层，`--example` 才连例子一起打。改动清单是加规则的地方，不改代码。

四条按顺序答，顺序即优先级：

1. `unmarked-additions` —— 这次改动里有没有哪一行不是你要求的，也没写进意图的哪一层。
2. `unresolved-piling` —— 意图声明的不确定项，这次加了几条、解了几条。
3. `boundary-creep` —— 这次改动有没有落在意图声明写「不干」的范围里。
4. `patch-over-framework` —— 这次是把现有框架加固了，还是在框架外面又补了一块。

**答「不是」就翻篇，不硬凑。** 每轮都命中四条的反思是假的——要么这四条太宽，要么你没真看。四条全空也是结论，照实写。

## 前置

```bash
cargo build --release && install -m755 target/release/qtfounder ~/.local/bin/qtfounder
qtfounder code reflect --example     # 能出四条说明装的是新版
```

## 反思工作流

### 第一步：拿清单

```bash
qtfounder code reflect --example
```

输出四条，每条带「看什么 / 为什么算缺陷 / 长什么样」。列表不是结论，是四道问答题。

### 第二步：逐条回看刚改的代码作答

拿这轮真实改动（`git diff` 的那批文件）过每一条。判断规则只有一句：**举得出具体一处才算命中**，举不出来就写「不是」。

- 命中 —— 说出是哪个文件哪一处，以及它将来会怎么咬人；
- 不命中 —— 直接进下一条，理由不写进路线图（不写「本次未发现」，空白即未命中）。

### 第三步：写回路线图

路线图在**独立 git 仓** `data/roadmap/` 里，不在本仓：它有自己的提交历史，所以改它要单独提交，只在本仓算不算写进去。

要写的那份是 `qtfounder/index.md`——qtfounder 的路线图正本，front matter 写着 `genre: roadmap`，文档站据此认出它是路线图。

**发现只进这一处**：`code reflect` 不存，`data/` 下别的文件也不存。你也不必另起笔记，路线图就是笔记。

落位按 [`docs/handbook/work/roadmap-maintenance.md`](../../../docs/handbook/work/roadmap-maintenance.md)：

- 要动手改的缺陷，进当前阶段的 `### 范围`，写成 `- [ ] <缺陷>（YYYY-MM-DD）`，日期即反思发生的那天；
- 改方向的（这轮证明某条路走不通），并进该节已有的「方向输入（日期 体感）」行，不新开小节；
- 还没验证、只是看着像的，按手册元原则标【待验证】，不混进正文当已验证的写。

### 第四步：按手册的三个自检收口

写完每一处都要过，三条都答才算写完：

- **验收标准** —— 这条写明什么算做完了吗？没写明的，补一句怎么算完；
- **待标定** —— 里面有没有拍脑袋的数字？随手写下的百分比与天数一律改成【待标定】，不给假精确；
- **前置关卡** —— 这条底座还没验证过的话，设计一个半小时能证明或证伪的验证，写在前面；证伪了就到此为止，不往下做。

### 第五步：提交并复跑

roadmap 仓先提交推送，再回父仓 bump 指针；然后复跑一次命令，确认清单本身没被改坏：

```bash
qtfounder code reflect
cargo test
```

## 示例

**题目**：这轮给 CLI 的 `data` 命令加导出，顺手把导入的分支也重构了，意图只声明了「加导出」。

跑 `qtfounder code reflect --example`，逐条：

- `unmarked-additions` —— **命中**。`data/export.rs` 导入分支那段不在意图的任何一层里，将来没人敢删。
- `unresolved-piling` —— 不命中。这轮没有新增未解项，前一轮那条当场验掉了。
- `boundary-creep` —— **命中**。意图写「只做导出、不动导入」，实际动了导入，边界挪了而意图没改。
- `patch-over-framework` —— 不命中。导出走的是已有的数据层，没在外面补块。

头两条命中的指向同一处改动，写在路线图里就是同一行：

```text
- [ ] 导入分支被无主改写，意图未声明（2026-10-30）
```

四条答出两条命中，其余照实留白，不补「本次未发现」。再过三个自检：上面那条写明了要改什么、没有拍脑袋的数字、不涉及底座验证，直接过。提交 roadmap 仓、bump 指针、复跑命令。

## 排错

- **`契约里没有 [[reflect]]`** —— 装的是旧二进制，跑前置那两条重建重装；或 `--rules` 指了一份没写反思段的自定契约。
- **`契约里没有这条反思规则「xxx」`** —— name 打错了，错误信息里会列全部可用 name。
- **每轮四条全命中** —— 清单写太宽了。回契约把 description 收窄到「你能举出具体一处」的程度，别放宽作答标准。
- **写完路线图没变化** —— 正本是 `data/roadmap/qtfounder/index.md`，那是个独立 git 仓，改完要单独提交，只在父仓 bump 指针不算写进去。
