# 表达改写

这段文字读起来不顺，问题多半出在讲法上：该定义的地方用了类比，该展开的地方压成口号，该给验收的地方写了决心。

规则在 `apps/qtfounder/src/cli/src/write/default-contract.toml`，机器只报形态；这份 Skill 写人怎么改。

## 何时用

- 文档被说「太密」「像口号」「写的什么玩意」
- 把草稿、对话、日志整理成正式文档
- 设计文档、路线图、README 或评审稿写完自查
- 同一段话改了三遍还是不顺

## 先跑一遍

```bash
qtfounder write . --rules apps/qtfounder/src/cli/src/write/default-contract.toml
```

四层各管什么：

| 层 | 查什么 | 典型改法 |
|---|---|---|
| empty | 空话密度 | 删掉，或说清具体指什么 |
| slogan | 口号句式 | 拆成条件、理由与反例 |
| reference | 正文指路 | 把结论写进正文 |
| structure | 标题与分节 | 补一级标题，按一节一件事分开 |

词与句交给 `language`，表格与列表交给 `docs`。三层都跑，问题按「一处只改一次」归堆。

## 这次遇到的毛病

### 1. 把结论压成口号

症状：一句话总纲加几条并列，每条只有判断，没有定义、步骤与边界。读者点头，但不知道怎么做。

改法：把一句话还原成一段。先定义对象，再给步骤，最后写什么不算。设计文档至少要有范围、构成、流程、约束与判断标准。

### 2. 用类比代替定义

症状：真相线、方向盘、站在沙子上。类比能帮一次理解，不能承担精确定义。

改法：第一次出现就给定义，类比只放在定义之后，一句带过。术语优先用对方已经有的词：指挥部、引擎、事件、报告、关卡。

### 3. 一句话塞多个判断

症状：分号把几个判断串在一起，逗号里还套着条件，读完不知道主句是什么。

改法：一句只推进一步。把「因为 A，所以 B；但 C 时 D」拆成「A。因此 B。C 时例外，理由是 D」。

### 4. 文体错位

症状：路线图写成洞察，索引写成设计稿，评审稿写成宣言。

改法：先看目的地。洞察写能被推翻的判断；路线图写先做什么、达成标志与后置代价；设计写定义、流程与边界；索引只做导航与阅读顺序。

### 5. 阶段没有门槛

症状：只写「先做 A，再做 B」，没写每段什么算做完，也没有推迟的代价。

改法：每段补三样：达成标志（可核对）、排序理由（依赖什么）、后置代价（晚做要多付什么）。

### 6. 并列项堆砌

症状：一行里五六个并列，谁也不展开。

改法：留两到三个最关键的，其余删掉或另起一段。并列项数量不是信息量。

### 7. 用绝对句式代替论证

症状：`只有……才`、`不是……而是`、`越……越`。读者不知道边界在哪，也不知道反例是什么。

改法：补条件与反例。写不出反例，说明这句话还没想清。

### 8. 结尾重复要点

症状：最后一段把前面的话再说一遍，或者升到「由此可见」。

改法：用一条能当场回答的问题收尾。例如「换掉一侧，另一侧要不要改？」

## 改写顺序

1. 定体裁：这是判断、计划、设计还是导航？选错体裁，后面怎么改都别扭。
2. 定范围：开头写清本文管什么、不管什么。范围不清，内容一定发散。
3. 定术语：每个新词第一次出现就定义，后面不改叫法。
4. 一段一意：一段只推进一步；推进不了就另起一段。
5. 给验收：每个结论配一个能核对的动作或问题。
6. 删收尾：删掉总结句与口号，留一条可检验的结论。

## 改写后复核

```bash
qtfounder write . --rules apps/qtfounder/src/cli/src/write/default-contract.toml
qtfounder language . --rules apps/qtfounder/src/cli/src/language/default-contract.toml
qtfounder docs . --rules apps/qtfounder/src/cli/src/docs/default-contract.toml
```

三个都要看，但不必都清零。`write` 报结构，`language` 报词句，`docs` 报块形状；同一处只改一次，改完再跑，别在三条命令之间来回拧。

## 坑

- 别用改写掩盖内容缺失：结构补上了，判断还是空的，读起来会更像样，也更难发现。
- 别把术语换成同义词：同一份文档里「事件」和「消息」混用，读者会以为是两样东西。
- 别把段落拆得过碎：一段一句同样难读；一段只推进一步，不是一段只有一句。
- 别删掉必要的重复：术语第一次定义后，关键结论可以在结尾复述一次；重复的是要点，不是整段。
- 契约里的词表不是判决：命中先读上下文，正常用法不动。

## 收尾自查

1. 换个体裁还成立吗？不成立，说明文体选错了。
2. 每个新术语都定义了吗？后面叫法一致吗？
3. 每段是不是只推进一步？
4. 每个阶段或结论都有可核对的标志吗？
5. 结尾是一条可检验的结论，还是又一次总结？
