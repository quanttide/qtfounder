# Studio 导航栏设计

量潮创始人工作台（qtfounder_studio）的导航栏（应用壳侧边栏）设计。

## 定位

导航栏是工作台的**应用壳**——承载品牌识别与页面导航的常驻结构。内容区随导航切换，导航栏本身不随页面变化。

## 分组结构（两组）

导航栏按**资产 / 领域（职能）**分组：

```
┌────────────┐
│     量      │  ← 品牌区
│ ─── 资产 ───│  ← 组标签 1
│  (fiction) │  ← 小说资产
│  (memory)  │  ← 记忆资产
│ ─── 领域 ───│  ← 组标签 2
│  (创作)    │  ← 创作职能
│  (情绪)    │  ← 情绪职能
│            │
│  (弹性区)  │  ← Spacer
└────────────┘
宽 80px · 白底
```

| 组 | 导航项 | 语义 | 图标（候选） |
| --- | --- | --- | --- |
| **资产**（有什么数据） | fiction | 小说资产：改稿轨迹/章节 | menu_book |
| | memory | 记忆资产：roadmap/context 文档 | memory |
| **领域**（有什么能力） | 创作 | 创作职能：写作/改稿工作流 | edit（或 create） |
| | 情绪 | 情绪职能：情绪状态（cli 数据接入） | insights |

### 分组依据

- **资产组**：围绕数据源（fiction/memory 是工作台的数据资产）——回答"有什么可以看"
- **领域组**：围绕职能/能力（创作、情绪等）——回答"有什么可以用"
- 注意：**创作是职能而非资产**——fiction（资产）是创作的对象/产出，创作（职能）是围绕 fiction 的活动（写作/改稿）；两者在导航中分属两组
- 分组 = 数据视角与能力视角的分离：资产可扩展（未来加数据源），领域可扩展（未来加职能）

## 结构设计

| 区域 | 尺寸 | 内容 |
| --- | --- | --- |
| 品牌区 | 顶部 20px + 品牌字 | "量潮"（16px / w700 / 主色 4F46E5） |
| 组标签 | 10px 小字（次级色） | "资产" / "领域" |
| 导航项 | 40×40 圆角容器（10px） | 图标（20px，主色）+ 浅紫底（E0E7FF，选中） |
| 弹性区 | Spacer | 预留：底部导航项/版本信息 |
| 总宽 | **80px** | 图标优先的窄栏 |

## 设计决策

### 1. 为什么 80px 窄栏

- 工作台是**内容密集型**界面，导航应让位给内容
- 图标优先：导航项用图标表达，hover/选中态承载语义
- 窄栏 + 大内容区 = 生态内其他 Studio 一致的布局比例

### 2. 为什么分组

- 单一列表随导航项增多会失去语义（资产与能力混排）
- 分组 = **语义分组**：用户先想"我要看数据还是用能力"，再定位导航项
- 与平台规划对应：资产组=数据层（fiction/memory），领域组=分析层（情绪）

### 3. 选中态设计

- 选中项：浅紫底（E0E7FF）+ 主色图标
- 未选中：透明底 + 次级色图标（预留）
- 组标签非交互（纯分组语义）

### 4. 为什么圆角容器而非文字

- 80px 窄栏放不下中文导航名
- 圆角容器 + 图标 = 可扩展导航单元：加资产/领域只需新增图标项

## 交互设计

| 交互 | 行为 |
| --- | --- |
| 点击导航项 | 切换内容区页面（壳内一级路由） |
| 选中态 | 浅紫底 + 主色图标（与品牌区同色系） |
| 组标签 | 不可点击，纯分组语义 |
| 内容区 | 随导航切换，导航栏自身不重绘（壳层稳定） |

## 演进方向

```
资产组扩展：未来新数据源（如 journal/report）→ 资产组加项
领域组扩展：未来新能力（如情绪详细分析/创作建议）→ 领域组加项
```

扩展规则：新增资产 = 资产组加图标项 + 路由表加一级路由；新增能力 = 领域组加图标项 + 路由表加一级路由。导航栏结构（品牌区/组标签/导航项区/弹性区）不变。
