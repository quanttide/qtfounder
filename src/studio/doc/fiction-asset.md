# 小说资产页设计（/assets/fiction）

量潮创始人工作台的小说资产页面（资产职能内部）。**页面结构直接对应 fiction 仓库的目录结构**——资产长什么样，页面就长什么样。

## 定位

展示 fiction 资产：按仓库现有目录组织，可浏览、可点击阅读。只读——创作活动在 /create。

## 页面结构（= 仓库结构）

fiction 仓库结构规则：

```
一级文件夹 = 一本小说     职场言情（主线）· 校园言情（if 线）· 重生言情（起步）
二级文件夹 = 一个阶段     1_灵感 → 2_脚本 → 3_初稿 → 4_改稿（校园另用 1_素材 → 2_提纲）
文件编号   = 排序         1_1_咖啡厅重逢 = 排序 1_1；6_2_海边散步 = 排序 6_2
无编号     = 未排序       偷看睡觉 / 再坐便利店 = 等待排序的素材
```

实际结构直接映射为页面层级：

```
小说资产
├── 职场言情
│   ├── 1_灵感/      12 篇（创作谈、人物关系、情绪日记…）
│   ├── 2_脚本/      20 篇（有编号=已定位，无编号=未排序：偷看睡觉…）
│   ├── 3_初稿/       9 篇（11_1_赏雪谈心 已排序在此）
│   └── 4_改稿/      19 章（完整排序 1_1 … 12_3）
├── 校园言情
│   ├── 1_素材 / 2_提纲 / 3_初稿 / 4_改稿 + README.md
└── 重生言情
    └── 1_灵感 / 2_脚本 / 3_初稿（尚无 4_改稿）
```

页面组件：
- **小说卡片**（职场言情 / 校园言情 / 重生言情）——对应一级文件夹
- 展开小说 → 阶段目录（照实显示各线阶段名）→ 文件列表
- 目录展开/收起（像文件浏览器），文件名即条目（含编号排序）

## 交互

| 动作 | 行为 |
| --- | --- |
| 点击线 | 展开/收起该线的流程目录 |
| 点击文件 | 打开阅读（详情页，只读） |
| 计数 | 目录名旁显示文件数（12 / 10 / 19） |

## 边界

- 只读：浏览 + 阅读，无编辑/写作（创作在 /create）
- 不发明视图：不搞漏斗/缺口/检索等抽象——目录结构本身就是视图

## 数据源

- `{fiction}/职场言情/{1_灵感|2_脚本|4_改稿}/*.md`（同 校园言情、重生言情）
- 实现：读取 fiction 顶层目录 → 各线子目录 → 文件列表（creative_repository 扩展）
