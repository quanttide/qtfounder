# 小说资产页设计（/fiction）

量潮创始人工作台的小说资产页面——资产组第一页。本文档依据 screens.md 的**资产页边界原则**设计：只挖掘资产结构、支持发现工作流，不做具体创作活动。

## 定位

小说资产页回答一个问题：**"小说这个资产，现在是什么结构、写到哪了、有什么可用的？"**

它是资产结构的事实视图——浏览、检索、阅读、状态可见；一切"做"的动作（写作/编辑/改稿）在 [/create 创作职能页](screens.md#3-创作职能页create)。

## 资产结构（数据源：fiction 仓库）

fiction 仓库的真实结构：

```
fiction/
├── 职场言情/                ← 主线创作
│   ├── 1_灵感/  12 篇       ← 情绪/构思（创作谈、人物关系、权力关系…）
│   ├── 2_脚本/  10 篇       ← 未成稿素材（男主演讲、包子店、再坐便利店…）
│   ├── 4_改稿/  19 章       ← 成稿章节（1_1 咖啡厅重逢 … 12_3 阳台看星星）
│   └── （3_初稿 空缺，11_x 缺口）
├── 校园言情/   19 篇        ← if 线（职场言情二十岁相遇的假设）
└── 重生言情/   4 篇         ← 起步
```

**结构特征**：
- **三线并行**：职场（主线）/ 校园（if 线）/ 重生（起步）
- **流程四态**：灵感（1_灵感）→ 脚本（2_脚本）→ 初稿（3_初稿）→ 改稿（4_改稿）
- **编号体系**：章节 = 序号_场景（1_1 咖啡厅重逢），11_x 整段缺口（规划中）

## 发现工作流（页面功能）

资产页承载**发现**：从资产结构中看到事实、定位可用内容。四个发现动作：

### 1. 浏览：资产结构总览

```
标题区：小说资产
├── 三线卡片：职场言情（主线）· 校园言情（if 线）· 重生言情（起步）
│    每卡：各流程文件数（灵感 x · 脚本 x · 改稿 x）
└── 点击线 → 该线的流程视图
```

**发现什么**：资产的全貌——几条线、各阶段有多少内容、主线在哪。

### 2. 挖掘：流程漏斗视图

选中一条线（如职场言情）后：

```
职场言情
├── 灵感池   12 篇（情绪/构思/人物设定）
├── 脚本池   10 篇（未成稿素材）
├── 改稿     19 章（成稿）
└── 缺口     11_x（规划中——见 roadmap/fiction.md）
```

**发现什么**：流程的瓶颈与缺口——素材多不多、哪些章节卡在脚本、哪段缺失。这是"资产结构挖掘"的核心：**漏斗即进度**。

### 3. 检索：过滤与搜索

- 按线过滤（职场/校园/重生）
- 按状态过滤（灵感/脚本/成稿/规划）
- 按关键词搜索（标题/场景名）

**发现什么**：定位特定内容（如"海边"场景的所有版本）。

### 4. 阅读：跳转详情

- 点击章节 → 章节详情页（正文阅读，只读）
- 点击文档 → 文档详情页（灵感/构思阅读，只读）

## 边界：什么不做

| 动作 | 归属 | 说明 |
| --- | --- | --- |
| 浏览/检索/阅读/状态 | ✅ 本页 | 发现工作流 |
| 章节详情阅读 | ✅ 本页（二级） | 只读 |
| **写作/编辑/改稿** | ❌ /create | 创作活动 |
| **创建素材/章节** | ❌ /create | 创作活动 |
| **规划落地**（把 11_x 拆成任务） | ❌ /create | 创作活动 |

**衔接而非承载**：本页发现缺口（如 11_x 规划中）时，可提供"去创作页处理"的**跳转引导**（导航到 /create），但不提供任何编辑能力——发现与创作在界面和心智上都分离。

## 设计要点

1. **结构即界面**：三线卡片 + 流程漏斗直接映射 fiction 仓库结构——不发明抽象视图，资产长什么样页面就长什么样
2. **漏斗即进度**：每个流程的文件数是事实（12 灵感/10 脚本/19 成稿/1 缺口）——"让创作可观测"意图的落地
3. **缺口可见**：11_x 等规划状态在漏斗中显式展示——发现工作流最有价值的输出是"看到缺什么"
4. **只读一致**：本页与详情页全部只读——零创作动作，边界清晰

## 与相邻页面的关系

```
/fiction（本页）  发现：资产结构/进度/缺口
    ↓ 跳转（只读）
章节详情页         阅读：正文
    ↓ 引导（不承载）
/create            创作：在缺口处写作/改稿（唯一创作入口）
```

## 数据源与实现

- 数据：`{fiction}/{线}/{1_灵感|2_脚本|4_改稿}/*.md`（文件系统）
- 缺口数据：`{memory}/roadmap/fiction.md`（11_x 规划）——跨数据源联合
- 实现：creative_repository 扩展（按线/按流程聚合计数 + 章节列表），页面组件（三线卡片/漏斗视图/过滤栏）

## 演进顺序

1. 三线总览 + 职场言情漏斗视图（替换当前 CreativeDesk 的混合展示）
2. 过滤/搜索
3. 缺口展示（联合 roadmap 数据）
4. 详情页跳转
