# 小说资产页设计（/fiction）

量潮创始人工作台的小说资产页面。**页面结构直接对应 fiction 仓库的目录结构**——资产长什么样，页面就长什么样。

## 定位

展示 fiction 资产：按仓库现有目录组织，可浏览、可点击阅读。

## 页面结构（= 仓库结构）

fiction 仓库结构（三线 + 每线流程目录）直接映射为页面层级：

```
小说资产
├── 职场言情
│   ├── 1_灵感/      12 篇（创作谈、人物关系…）
│   ├── 2_脚本/      10 篇（男主演讲、包子店…）
│   └── 4_改稿/      19 章（1_1 咖啡厅重逢 … 12_3 阳台看星星）
├── 校园言情
│   ├── 1_灵感/      …
│   └── …
└── 重生言情
    └── …
```

页面组件：
- **线卡片**（职场言情 / 校园言情 / 重生言情）——对应仓库顶层目录
- 展开线 → 流程目录（1_灵感 / 2_脚本 / 4_改稿）→ 文件列表
- 目录展开/收起（像文件浏览器），文件名即条目

## 交互

| 动作 | 行为 |
| --- | --- |
| 点击线 | 展开/收起该线的流程目录 |
| 点击文件 | 打开阅读（详情页，只读） |
| 计数 | 目录名旁显示文件数（12 / 10 / 19） |

## 边界

- 只读：浏览 + 阅读，无编辑/写作（创作在 /create）
- 不发明视图：不搞漏斗/缺口/检索等抽象——目录结构本身就是视图

## 数据源

- `{fiction}/职场言情/{1_灵感|2_脚本|4_改稿}/*.md`（同 校园言情、重生言情）
- 实现：读取 fiction 顶层目录 → 各线子目录 → 文件列表（creative_repository 扩展）
