# 思考职能页设计（/think）

量潮创始人工作台的思考职能页——**思绪结构化**（思考云原型）：把每天散乱的思绪处理成 事实 / 感受 / 行动。

## 定位

写作页处理**作品**（素材→正文），思考页处理**思绪**（杂乱→结构化）。依据 08-14 日志的作者意图：

> "把各种各样的情绪，以一种结构化的方式装进一个 Agent 里面"——承载压力
> "区分事实、感受、行动等等"——结构化处理器（思考云原型）
> "结构化这些思绪之后，它的意义不完全是代替思考，而是作为思考的垫脚石"
> "每天不把自己的想法处理干净，很难睡得着"——每日清理动力

## 数据源：日志（现有结构）

作者："把它先做到日志里面"——结构化落在 memory/journal（现有结构）：

```
memory/journal/default/YYYY-MM-DD.md   ← 每日日志（思绪的存放处）
```

思考页 = 日志的结构化工作台：**日志是输入，结构化结果是输出**。

## 页面结构

```
思考
├── 日志列表（按日期：2026-07-29 … 2026-08-15）  ← 现有结构镜像
└── 打开某天日志 → 结构化视图：
    ├── 事实（发生了什么）
    ├── 感受（情绪如何）
    └── 行动（要做什么/做了决定）
```

## 基本功能

| 功能 | 行为 |
| --- | --- |
| 日志列表 | 按日期浏览 memory/journal 日志（同资产页目录结构） |
| 结构化视图 | 把一天日志处理成 事实/感受/行动 三区 |
| 结构化记录 | 处理结果（事实/感受/行动）沉淀到当日日志（结构化段） |
| 处理状态 | 当天是否已处理（对应"每天处理干净"） |

### 结构化格式（沉淀到日志）

```
## 结构化（思考云）
事实：…
感受：…
行动：…
```

## 边界

- **不代替思考**：结构化是垫脚石——把思绪摆出来，不是自动得出结论
- 本页写操作：仅结构化段的记录（不动日志正文叙事）
- 不做写作页的事（作品编辑在 /write）

## 设计要点

1. **日志即输入**：不发明新的输入界面——日志是思绪的天然存放处（作者"先做到日志里面"）
2. **三区结构**：事实/感受/行动——思考云原型的核心（对齐作者原话）
3. **每日清理**：处理状态 = 当天是否完成结构化（对应睡眠动力）
4. **垫脚石**：结构化结果可被后续功能消费（如情绪趋势）

## 演进

1. 日志列表（复用资产目录引擎——memory 契约）

3. 处理状态标记（当天已处理/未处理）
4. （未来）LLM 辅助抽取（复用 cli 情绪维度模式）
