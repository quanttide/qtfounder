# Screens 页面设计思路

量潮创始人工作台各页面的设计思路。页面按**职能**组织（资产 / 创作 / 情绪），与 [../navigation.md](../navigation.md) 和 [../router.md](../router.md) 对应。

## 页面总览

| 路由 | 页面 | 职能 | 状态 |
| --- | --- | --- | --- |
| `/assets` | 资产职能页（聚合） | 资产 | 规划 |
| `/assets/fiction` | 小说资产页 | 资产 | 规划（当前 CreativeDesk 迁移） |
| `/assets/memory` | 记忆资产页 | 资产 | 规划 |
| `/write` | 写作职能页 | 创作 | 规划 |
| `/think` | 思考职能页 | 情绪 | 规划 |
| 阅读详情 | 章节/文档阅读页 | 资产（三级） | 规划 |

当前实现：单页（CreativeDesk），位于 main.dart。

---

## 资产职能（/assets）

### 1. 资产职能页（/assets）

**定位**：资产的聚合入口——"有哪些资产"。

**数据源**：资产列表（fiction、memory 及未来新增）。

**界面设计**：
```
标题区：资产
资产列表（卡片）：
  ├── 小说（fiction）——职场言情/校园言情/重生言情
  ├── 记忆（memory）——roadmap/context 等
  └── （未来：journal/report/archive…）
```

**设计要点**：
- 资产 = 数据源集合：聚合入口列出所有资产，点击进入各资产页
- 资产卡片显示简要描述（资产类型 + 结构提示）
- 新资产 = 列表加卡片（导航栏结构不变）

### 2. 小说资产页（/assets/fiction）

**定位**：fiction 资产的查看入口——**页面结构直接对应仓库目录结构**。

**界面设计**（= 仓库结构镜像）：
```
小说资产
├── 职场言情
│   ├── 1_灵感/   12 篇
│   ├── 2_脚本/   10 篇
│   └── 4_改稿/   19 章
├── 校园言情
└── 重生言情
```

**设计要点**：
- **结构即界面**：目录树（线 → 流程目录 → 文件），资产长什么样页面就长什么样
- 交互：展开/收起、点击阅读（只读）、目录旁计数
- **只读**：浏览 + 阅读，无编辑/写作（创作在 /write）——详见 [fiction-asset.md](fiction-asset.md)

### 3. 记忆资产页（/assets/memory）

**定位**：memory 资产的查看入口——同样按目录结构展示。

**界面设计**（= 仓库结构镜像）：
```
记忆资产
├── roadmap/   5 篇（fiction、index、voice-input…）
├── context/   6 篇（fiction-plot、fiction-adaptation…）
├── journal/   …
└── …
```

**设计要点**：与小说资产页同模式——目录树镜像 + 只读阅读。

## 写作职能（/write）

### 4. 写作职能页（/write）

**定位**：创作活动的唯一承载——"做创作这件事"。

**数据源**：fiction（章节）+ memory（方法文档如 fiction-adaptation 转化规律）。

**界面设计**：
```
标题区：创作
创作工作流：
  ├── 当前焦点：11_x 世界扩张（规划中 → 脚本 → 改稿）
  ├── 素材池：2_脚本 未成稿（演讲 / 包子店 / 再坐便利店）
  ├── 方法速查：素材→正文转化规律（8 条）
  └── 写作入口：选章节 → 进入编辑
```

**设计要点**：
- **唯一创作承载**：所有创作活动（写作/编辑/改稿/规划落地）只在此页；资产页发现的内容在这里转化为创作动作
- 焦点驱动：当前创作目标置顶，素材池与方法速查作为配件
- 对齐平台意图"让表达自然生长"

## 思考职能（/think）

### 5. 思考职能页（/think）

**定位**：情绪状态的观察入口——"创作背后的状态"。

**数据源**：cli health 输出（git 历史 + LLM 情绪维度）。

**界面设计**：
```
标题区：情绪状态
情绪概览：当前主导情绪 + valence/arousal
趋势：近 N 天情绪曲线
预警：warning_signs 列表
```

**设计要点**：
- cli 算、studio 看的分工（不重复实现分析）
- 情绪与创作对照：同一时间轴上的创作轨迹 + 情绪曲线——呼应"情绪闭环"

---

## 三级页面（阅读）

### 6. 阅读页

**定位**：阅读资产文件（章节/文档）的只读视图。

**数据源**：资产文件（按路由参数定位）。

**界面设计**：标题 + 正文（Markdown 渲染），资产内导航（上一个/下一个）。

**设计要点**：纯阅读，无编辑；从资产页点击进入。

---

## 页面共同原则

1. **壳内一致**：所有页面共享导航栏壳，页面只负责内容区
2. **数据源直读**：桌面端直接读文件系统，Web 端经 provider API
3. **结构即界面**：资产页直接映射仓库目录结构，不发明抽象视图
4. **资产页只读**：浏览/阅读/状态可见；创作动作唯一归属 /write
5. **职能平级**：资产（有什么）/ 创作（怎么写）/ 情绪（状态如何）——三个职能三个问题

## 演进顺序

1. `/assets` + `/assets/fiction`（目录树，替换当前 CreativeDesk）
2. `/assets/memory` + 阅读页
3. `/write`（创作工作流）
4. `/think`（cli 数据接入）
