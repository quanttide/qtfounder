# 创作职能页设计（/create）

量潮创始人工作台的创作职能页——**创作工作流的显性视图**：fiction 四阶段（灵感 → 脚本 → 初稿 → 改稿）作为流程呈现，文件挂载在流程位置上，可推进。

## 定位

资产页显示结构（有什么），创作页显示**流程**（创作进行到哪、如何推进）。fiction 的阶段目录就是工作流——显性化 = 以流程形态呈现 + 提供推进动作。

## 页面结构（流程视图）

```
创作
├── 流程条：1_灵感 → 2_脚本 → 3_初稿 → 4_改稿
│            （每阶段：语义 + 文件数）
├── 各阶段挂载文件：
│   1_灵感   [创作谈][人物关系][情绪日记]…      [+ 新建]
│   2_脚本   [2_2_男主演讲][偷看睡觉]…          [+ 新建]
│             每个文件可「推进到初稿」
│   3_初稿   [11_1_赏雪谈心][7_1_酒吧表白 2]…   [+ 新建]
│             每个文件可「推进到改稿」
│   4_改稿   [1_1_咖啡厅重逢]…[12_3_阳台看星星] [+ 新建]
└── 文件点击 → 写作视图（编辑 + 保存）
```

## 功能

| 操作 | 行为 |
| --- | --- |
| 流程条 | 四阶段顺序 + 语义（灵感=源头/脚本=素材/初稿=成文/改稿=定稿）+ 计数 |
| 文件推进 | 文件从当前阶段推进到下一阶段（脚本→初稿→改稿），即创作流的位置移动 |
| 新建 | 在指定阶段创建文件（按阶段命名习惯） |
| 文件点击 | 写作视图：编辑 + 保存写回 |

## 工作流显性化的核心

- **流程条**：一眼看到创作流全貌（四阶段 + 每阶段体量）
- **推进动作**：创作流的操作 = 把内容从一个阶段移到下一个——"写好了脚本"这一动作显式化
- **文件位置 = 流程位置**：文件在哪个阶段，就是创作进行到哪（真实目录状态，不发明状态字段）

## 边界

- 推进 = 文件移动到下一阶段目录（真实文件操作）
- 本页唯一可写（新建/编辑/推进）；资产页只读
- 不做其他职能的事

## 演进

1. 流程条 + 各阶段文件列表（复用引擎数据，流程形态呈现）
2. 推进操作（移动到下一阶段）
3. 新建 + 写作视图（编辑/保存）
