# Studio 文档

本目录描述当前代码、当前边界和已确认的下一步。归档业务层的详细设计不再作为当前实现文档；需要历史设计时查 Git 历史或归档代码。

## 定位

Studio 的定位是创作现场的观察层：让创作过程可见。规划中的资产、创作、思考三个职能分别回答「有什么」「怎么写」「状态如何」；当前已落地第一个模块（资产抽查），其余页面待重建。

## 当前形态

`lib/main.dart` 渲染首页入口列表；`lib/asset/` 是资产抽查模块（扫描、批次卡片流、保留/删除）。数据契约在 `assets/contracts/`，运行时尚未接入。

## 文档

- [架构](architecture.md)：当前分层、依赖方向、数据契约、归档业务层与重建约束
- [资产抽查](asset.md)：扫描范围、状态机、文件操作与边界
- [数据源与契约](data-sources.md)：fiction 与 memory 的结构和路径
- [页面规划](planned-ui.md)：导航、路由、资产、创作、思考与审阅页面
- [路线图](../ROADMAP.md)：当前状态与下一步

## 阅读顺序

新加入的人先读根目录 [README](../README.md)，再读架构；要恢复业务层时读数据源与页面规划。`planned-ui.md` 里的内容都是规划，不是当前实现。

## 维护规则

文档跟着代码走：新增能力时更新对应文档，能力未实现时标为规划，不把归档代码的设计写成当前实现。子模块文档不链接父仓文件，跨仓库历史只写路径文本。
