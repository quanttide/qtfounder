# Screens 页面设计思路

量潮创始人工作台各页面的设计思路。页面按导航栏分组（资产 / 领域）组织，与 [navigation.md](navigation.md) 和 [router.md](router.md) 对应。

## 页面总览

| 路由 | 页面 | 组 | 状态 |
| --- | --- | --- | --- |
| `/fiction` | 小说资产页 | 资产 | 规划（当前创作现场迁移） |
| `/memory` | 记忆资产页 | 资产 | 规划 |
| `/create` | 创作职能页 | 领域 | 规划 |
| `/emotion` | 情绪职能页 | 领域 | 规划 |
| `/fiction/chapters/:id` | 章节详情页 | 二级 | 规划 |
| `/memory/:category/:name` | 文档详情页 | 二级 | 规划 |

当前实现：单页（CreativeDesk，混合展示改稿 + 文档矩阵），位于 main.dart。以下为分组后的页面设计。

---

## 资产组页面

### 1. 小说资产页（/fiction）

**定位**：fiction 数据资产的查看入口——"小说写到哪了"。

**数据源**：`{fiction}/职场言情/4_改稿/*.md`（章节列表，数值排序）。

**界面设计**：
```
标题区：小说资产（+ 子分类切换：职场言情 / 校园言情 / 重生言情）
改稿轨迹列表：章节卡片（编号 + 标题 + 状态）
  ├── 成稿章节（1_1 咖啡厅重逢…）
  ├── 规划章节（11_x 世界扩张——roadmap/fiction.md 驱动）
  └── 点击 → 章节详情页
```

**设计要点**：
- 列表 = 改稿轨迹的具象化：章节即情绪单元，轨迹即治疗轨迹（对齐平台意图"让创作可观测"）
- 分类切换（职场/校园/重生）呼应 fiction 仓库结构——三线创作并行可见
- 规划章节与成稿章节同列表展示：**进度可见性**（写到哪、卡在哪）

### 2. 记忆资产页（/memory）

**定位**：memory 数据资产的查看入口——"方向与方法的沉淀"。

**数据源**：`{memory}/roadmap/*.md` + `{memory}/context/*.md`。

**界面设计**：
```
标题区：记忆资产
文档矩阵（按分类分组）：
  ├── roadmap（方向）：fiction / index / voice-input …
  ├── context（方法）：fiction-plot / fiction-adaptation …
  └── 点击 → 文档详情页
```

**设计要点**：
- 分组展示 = memory 的认知科学框架（方向层 roadmap / 方法层 context）直接映射界面
- 文档名 + 分类标签（[roadmap] [context]）——延续当前 CreativeDesk 的创作域矩阵
- 意图对齐"让记忆可积累"：沉淀可见，检索即用

## 领域组页面

### 3. 创作职能页（/create）

**定位**：创作活动的入口——"做创作这件事"，区别于查看资产。

**数据源**：fiction（章节）+ memory（方法文档如 fiction-adaptation 转化规律）。

**界面设计**：
```
标题区：创作
创作工作流：
  ├── 当前焦点：11_x 世界扩张（规划中 → 脚本 → 改稿）
  ├── 素材池：2_脚本 未成稿（演讲 / 包子店 / 再坐便利店）
  ├── 方法速查：素材→正文转化规律（8 条）
  └── 写作入口：选章节 → 进入编辑
```

**设计要点**：
- **职能 ≠ 资产**：/fiction 看"有什么"，/create 做"怎么写"——页面承载创作动作（选素材 → 用方法 → 写作）
- 焦点驱动：当前创作目标（11_x）置顶，素材池与方法速查作为工作台配件
- 对齐平台意图"让表达自然生长"：创作所需的一切（素材/方法/目标）在一个页面

### 4. 情绪职能页（/emotion）

**定位**：情绪状态的观察入口——"创作背后的状态"。

**数据源**：cli health 输出（git 历史 + LLM 情绪维度：dominant_mood / valence / arousal / warning_signs）。

**界面设计**：
```
标题区：情绪状态
情绪概览：当前主导情绪 + valence/arousal 指标
趋势：近 N 天情绪曲线（cli track CSV）
预警：warning_signs 列表（如有）
```

**设计要点**：
- 数据来自 cli（不重复实现分析）——**clié 算、studio 看**的分工
- 情绪与创作对照：同一时间轴上的创作轨迹 + 情绪曲线——呼应"情绪闭环"（记录→创作→观察→反哺）
- 对齐平台意图"让状态可感知"：不可言说的情绪状态被量化可见

## 二级页面

### 5. 章节详情页（/fiction/chapters/:id）

**定位**：阅读单个章节正文。

**数据源**：`{fiction}/职场言情/4_改稿/{id}_*.md`。

**界面设计**：正文阅读（标题 + 全文）、章节导航（上一章/下一章）、状态标注（成稿/脚本/规划）。

**设计要点**：从"看到章节"到"读章节"——资产页的深化；状态标注让改稿轨迹语义完整。

### 6. 文档详情页（/memory/:category/:name）

**定位**：阅读单个 memory 文档。

**数据源**：`{memory}/{category}/{name}.md`。

**界面设计**：文档阅读（MyST Markdown 渲染）、同分类文档导航。

**设计要点**：记忆资产的阅读视图——沉淀的方法/方向可随时查阅。

---

## 页面共同原则

1. **壳内一致**：所有页面共享导航栏壳（品牌区/分组导航），页面只负责内容区
2. **数据源直读**：桌面端页面直接读文件系统（creative_repository），Web 端经 provider API
3. **资产与职能分离**：资产页（看数据）与职能页（用能力）界面形态不同——资产页是列表/矩阵，职能页是工作流
4. **状态可见**：每个页面都有"进度/状态"语义（改稿轨迹、沉淀分类、情绪指标）——平台意图"可观测"的落地

## 演进顺序

1. `/fiction` + `/memory`（创作现场拆分，替换当前 CreativeDesk）
2. 章节详情页 + 文档详情页（列表 → 详情）
3. `/create`（创作工作流，结合 11_x 与素材池）
4. `/emotion`（cli 数据接入）
