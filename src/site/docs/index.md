# 量潮创始人官网 — 设计

## 定位

创始人官网。展示我对外交付的成果与正在进行的创作活动——从"作品集"到"创作现场"：访客看到的不是简历，而是创作系统的实时窗口。

核心问题只有一个：**这个人正在创造什么？**

## 首页

### Hero

一句话说明我在做什么、交付什么。附一个**实时锚点**：当日创作动态摘要。

> 创业者，写作者。
> 已交付的产品与文字，定义了我的认知。

实时锚点（数据来自当日 commit）：

```
今日 · 小说 342 字 · 改稿 1 篇 · journal 1 篇
```

### 创作流（时间线）

首页核心区块。按时间倒序混合展示近期创作活动，每条含类型标签、内容、日期：

| 类型 | 素材来源 | 展示形态 |
|------|---------|---------|
| 日记 | memory journal | 一句话摘录 |
| 小说 | fiction 仓库 | 标题 + 字数 |
| 游戏 | qtgame-* 仓库 | 版本里程碑 |
| 文章 | 已发布思考 | 标题 + 链接 |

最多展示 10 条，附"更多 →"链接到 `/works`。

### 创作域

四个创作域各占一格，展示**活状态**而非静态卡片：

| 域 | 展示内容 |
|----|---------|
| 小说 | 草稿数、最近改稿、下一步 |
| 游戏 | 各项目当前版本、进行中的工作 |
| 工具 | 语音输入 / CLI / 第二大脑 的迭代记录 |
| 思考 | 最近发布的文章与机制显性化产出 |

每格：当前状态 + 最近动态 + 下一步计划。

### 关于

简要背景：做过什么、能做什么、关注什么。不超过三段话。不写"在探索"——只写已确认的。

### 联系

- GitHub
- 邮件
- 其他社交链接

不需要表单。

## 作品页面 `/works`

### 路由

`/works` — 独立页面，从首页"更多"进入。顶部包含返回首页的链接。

### 列表

按时间倒序排列。每项：

```
[类型] 标题              日期
       一句话说明
```

示例：

```
[改稿] 咖啡厅重逢         2026-05
       十年后偶然在一家咖啡厅重遇，两个人都没想到会以这样的方式再见。

[文章] 认知与叙事的一致性  2026-04
       探讨写作中认知框架对叙事结构的影响。
```

类型标签用灰色文字，不加背景色、边框、badge。

### 筛选

页面顶部提供文字链接切换视图：`全部 / 改稿 / 文章 / 游戏 / 工具`。选中状态为加粗，其余正常字重。无选中则显示全部。

### 空状态

筛选后无结果：显示 `暂无匹配作品`，灰色文字。

### 作品详情

#### 改稿轨迹（过程即作品）

小说详情页展示初稿 → 改稿的轨迹：每个版本附日期与一句话说明。把"对细节的反复打磨"可视化——这是与静态作品集最差异化的展示，也是创作现场的核心证据。

```
v0 初稿      2026-04  完整初稿，约 3200 字
v1 叙事调整   2026-05  调整时间线，补全动机
v2 语言润色   2026-05  精简对白，统一视角
```

其他类型作品（文章/游戏/工具）详情暂不设计，链接到外部原文或仓库。

## 风格原则

### 克制

- 不加多余的视觉元素。没有动画、没有渐变背景、没有卡片阴影。
- 颜色只用黑色、白色、灰色。
- 字体：sans-serif，系统字体栈。

### 文字优先

- 页面内容就是文字。不加图表、插图、icon。
- 时间线是唯一的"图形"——用日期列、标签、文字密度表达创作节奏。
- 排版是唯一的视觉设计手段：字号、字重、行距、间距。

### 留白

- 每个 section 上下 5rem padding。
- 行距 1.8。
- 页面宽度 720px。

## 技术决策

- React 19 + TypeScript + Vite
- 纯 CSS，无框架
- 部署到 GitHub Pages
- 无后端，纯静态
- **数据生成**：构建脚本从子模块 git commit 生成活动流 JSON（journal 摘录、小说更新、游戏版本），避免手工维护；`data/works.ts` 保留为静态作品清单，与活动流互补
